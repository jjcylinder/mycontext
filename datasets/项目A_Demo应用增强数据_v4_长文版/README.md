# 项目 A Demo V4：独立长文对照集

已扩写全部 **39 份模拟文档、12 份模拟会议材料，共 193 个记录段落**。基线 V3 保持原样，群消息不扩写。原记录编号、时间、元数据、业务断言、评测问题与参考答案保持不变。

扩写由模型逐来源完成，再以单独请求复核；作者未接触评测题。新增的是来源相关背景、操作考虑和有条件的讨论，不能当作新增的已完成业务事实。这是受控长文对照集，仍保留编号互联，也不是生产环境的长会议逐字稿。

## 验证结果与边界

- 3362 项数据完整性与导入不变量检查通过；三个 profile 均可加载，实际 DWS 正文与扩写文本一致。
- 聊天源文件、聊天记录、评测目录和非模拟周报逐字节保持；原 V3 文件未修改。
- 新版使用独立 `v4-expanded` 数据标识。图谱和向量索引需重新建立，未复制旧版事实图谱。
- 当前模型实际分词检查：全部扩写文档/会议 chunk 最长 428 token，低于 512 输入上限；应用范围最长 415 token。
- 原有聊天会话合并产生的 20 个 chunk 中，17 个仍超过当前 embedding 的 512-token 上限，且与 V3 完全一致。正式 B/C 对照前应统一解决这一既有截断问题，可选共享分段改进或更长输入的 embedding。短消息无需扩写。
- 原生聊天分段使用 `cl100k_base`，验证拒绝离线时悄悄退化为字符数估算。
- 16 项代码测试通过。五题回归参数已核对为 TR04、AM03、PO03、X01、X03，仅 BC；本轮未实际运行题目，未运行 A，也没有新的 B/C 正确率。

完整检查见 [validation.json](audit/validation.json)，原文位置映射见 [expansion_map.json](audit/expansion_map.json)，生成与复核统计见 [authoring_summary.json](audit/authoring_summary.json)。生成及复核原始请求保存在独立运行目录，位置在统计文件中。

## 使用

从 `/home/jcylinder/codex/mycontext/kl-graph` 执行：

```bash
.venv/bin/python -m project_demo.app --chatgpt \
  --dataset '/home/jcylinder/codex/datasets/项目A_Demo应用增强数据_v4_长文版' \
  --data-dir data/project_demo/v4-longform-runtime --port 8767
```

打开 `http://127.0.0.1:8767`，导入“应用核查”。首次导入需要从新版正文重新提取事实并建立索引。

默认推荐 `app_focus`；`full_v3` 是兼容参数名，读取当前 V4 全量模拟材料。`full_with_report` 还包含原样保留的非模拟周报，外发限制不变。不要同时导入 overlapping normalized 视图。仅既定业务 profile 进入模型，README、evaluation、audit 和生成日志均不属于检索语料。

目标是检验 C 的事实提炼及关联优势；本版本并未证明 C 已领先。当前 C 仍优先装入完整原文，事实只补充到剩余预算，这会限制长文下的提炼收益。数据构建条件、下一轮比较口径和 Qwen embedding 建议见[扩写数据集构建说明](../扩写数据集构建说明.md)。

GitHub 仓库收录模拟材料，可加载 `app_focus` 和 `full_v3`。包含非模拟原周报的 `full_with_report` 仅在持有原始资料的本地数据集中可用。
