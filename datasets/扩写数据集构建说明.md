# MyContext 独立扩写数据集：构建与验证约定

目标是在公正条件下检验 C 的事实提炼、实体关联和图谱是否带来增益。扩写让原文包含更多业务背景、操作考虑和讨论内容，使原文不再几乎等于事实摘要；数据长度本身不是 C 更优的证据。

## 本轮控制的变量

以 `C:\Users\jcyli\Downloads\项目A_Demo应用增强数据_v3` 为基线，新版单独保存为工作区下的 `项目A_Demo应用增强数据_v4_长文版`。

- 扩写全部模拟文档与会议来源，包括应用范围外的原有模拟材料，避免只为五道回归题定制材料。
- 保留记录 ID、来源 ID、标题、时间、项目提示、回复和附件引用等元数据。原有断言在对应段落中逐字保留一次；位置分布在段内，不统一置顶。
- 聊天来源文件、聊天记录正文、评测问题、参考答案以及非模拟周报保持不变。
- 新增内容以来源相关的背景、核查方法、操作考虑和有条件的讨论为主，不追加已完成工作、通过结论、责任人或截止日期。
- 扩写模型逐来源阅读业务原文，不接触评测题和参考答案。另一次模型请求检查语义漂移，生成和复核记录单独留存，不进入检索语料。
- 本轮保留编号互联，先考察正文长度与信息密度的影响。自然别名、隐式关联等变量留待独立数据版本处理。

这是一版保留既有业务事实的**受控长文对照集**，不是采集自生产环境的真实长文基准。为避免编造事实，会议增加的是模拟议题展开和待核查讨论，不冒充具名逐字发言。生成与复核来自同一模型系列的不同请求，不能视为独立人工认证。

## 实际输入与索引隔离

扩写同步更新 `corpus/documents/`、`corpus/meetings/` 和三个重叠的 `normalized` 视图。Demo 仍会校验正文与来源锚点一致，DWS 导出使用完整扩写正文。

新版 manifest 使用 `project_a_application_v4_expanded`，运行数据标识采用 `project-a-v4-expanded-…`，与 V3 独立。不能把 V3 的事实图谱或原文向量库直接复制到新版下作为新结果。`full_v3` 仅保留为兼容的 profile 参数名，在新版目录里读取新版全量材料。

业务输入只允许既定 normalized profile；`evaluation/`、`audit/`、README、构建脚本、生成/复核提示词和本说明都不进入检索。

验证包含：全量与子集记录一致性、元数据及截止时间保持、原断言保留、聊天与评测文件字节一致、DWS 正文一致，以及使用当前 embedding 的实际 tokenizer 检查文档/会议 chunk。聊天保持原状，已有聊天长 chunk 的截断风险会单列披露，不因扩写悄悄修改。

## 如何判断 C 的优势

默认回归仍只有 **TR04、AM03、PO03、X01、X03** 五题，比较 B/C，不运行 A。长文版尚未实测前，不能沿用 V3 的 B=0/5、C=2/5 结果。

两组必须使用相同业务材料、截止时间、回答模型、embedding、原文切分、基础关键词/向量召回和最终输入预算。除了完整答对率，还要核对：

1. 必要结论、否定、条件、项目与版本边界、责任分工是否齐全，引用是否真正支持结论。
2. 必要证据在哪个阶段丢失：召回、重排、预算装入，还是最终回答。
3. 提炼事实的忠实性、来源覆盖和压缩比例；不能把原有断言长度占比直接当作已测的事实提炼收益。
4. 同样预算下的有效证据覆盖，以及建库、抽取、重排和回答的成本；共用缓存不算独立速度优势。

五题已参与开发，结果用于回归诊断。稳定性和泛化结论还需要另设未参与调试的问题，不能把开发题改善推广为全面领先。

## 当前 C 实现需要关注的限制

当前 C 先选择完整原文，再把能追溯到已选原文的图谱事实加入剩余空间。图谱已经参与找资料和重排，但提炼结果尚未作为可独立计入预算的紧凑证据表示。

因此，正文变长可能同时加重 B、C 的装入压力，甚至让 C 的额外候选扩大重排输入。这不是简单增加向量维数能解决的问题。下一步应根据长文诊断决定是否让 C 使用保留对象、条件、时间与出处的事实单元，并按需回查原文；同时检查事实遗漏和错误提炼，不能仅用短摘要获得表面压缩优势。本轮数据构建不修改该选择机制。

## 关于 Qwen embedding

2026-11-21 补充核实：官方已提供云端 `qwen3.7-text-embedding-flash`，默认 1024 维，输入能力约 128K。此前仅检索到开源 Qwen3-Embedding 系列，关于未查到 Qwen3.7 型号的结论不充分，现更正。Flash 尚未找到官方可下载权重；本地 1024 维候选为开源 Qwen3-Embedding-0.6B。开源系列与云端 Flash 不是同一个型号。[Flash 官方模型页](https://help.aliyun.com/zh/model-studio/qwen3-7-text-embedding-flash) · [本地 0.6B 模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B) · [部署评估](/home/jcylinder/codex/Qwen_Embedding_Flash_1024维部署评估.md)

当前 Demo 使用 `BAAI/bge-small-zh-v1.5`，512 维，实际模型输入最多约 512 token。向量维数与输入长度是两个独立参数；512 维本身不能证明效果不够。Qwen3-Embedding 值得作为更长输入及多语言语义召回的候选，质量收益需在业务数据上实测。

先固定当前模型完成数据版本，然后在同一扩写版上让 B、C 一起更换 embedding、重建向量索引，保持其余配置一致。即使使用 32K 模型，也需合理分段，不能默认把整篇长文压成一个向量最合适。更好的 embedding 也会增强 B，不能预设它扩大 C 的领先幅度。8B 更适合已有 GPU 推理服务的情况；本机部署需核实资源，也可评估较小型号。
