# TR04 事实关联与选证覆盖修复

2026-11-22。本轮修复在 Demo 读取既有事实、组织证据和预算装入的路径生效。数据使用已有 ChatGPT 抽取快照，关系修复采用查询时的结构化投影。原生 SQLite 的历史主宾语及向量索引仍保留历史表示，直接调用原生查询服务的其他客户端需要另行接入该投影。

## 修复内容

1. 已抽取事实涉及“那张”“这两列”等指代时，沿截止时可见、同会话、同线程、同项目的回复链补齐证据，记录原始发言来源与上下文来源。遇到缺失来源、循环或跨范围关系时标记未解析，查询适配层过滤该紧凑事实。原文仍可参加原文检索。
2. 等待材料的事实增加结构化交接字段，包括等待活动、明确的等待方、明确的提供方、材料及完整引文。发布等待应用申请能够表示为发布孙工等待应用侧的发布申请。发言人和等待方分开记录，原文未写明的提供方保持未知。
3. 职责补查使用本题候选对应的事实，覆盖 DELEGATE 及具有第一人称明确承诺的 DECISION、ACTION_ITEM。补查受问题角色、业务范围和原文约束。所有已确认职责及交接原文先共同计入预算，再装入其他候选。整体超预算时，覆盖审计记录缺口及预算原因。
4. 证据原文携带完整上下文来源，最终展示对明确指代保留回复链。T08-04 的承诺连同 T08-03 的两列名称和 T08-02 的 QA-A27 对象一起进入输入及展示校验。

## 评判纠正

T08-03 指出期望答案与判定说明缺失，应用协调在 T08-04 承诺“我补这两列”。事实库已正确抽取两项承诺。此前两次 V4 Pro 的候选包含 T08-04，最终输入均遗漏。因此，“应用补判定说明没有原文依据”只能描述当时已选材料的局限，不能作为整个数据集的事实判断。此前对该职责的笼统否定需要以这条完整证据链纠正。

两份输入都保留 T08-02/03/04 的完整承诺链、T04-06/07 的缺陷分析链、ATR0-S04 的登记分工、XTR3-06 的模型等待材料、XTR3-07 的发布申请，同时保留 XTR2-04 的未回归分支和 XTR3-05 的正式环境现状。两种等待关系均进入最终事实上下文。
